## Strict published result contract (2026-10-02)

- `publishedPairingResult.ts` is the shared score/result decoder. A named game requires both seats, `decided=true`, and one complete recognized result token. Pending text, numeric substrings and unknown values never establish a score, finished game, resolved live fraction or completed event. Explicit forfeits award points but do not count as played games; pending named assignments retain opponent and colour history. Solo awards use only the occupied seat, including explicit zero from legacy `decided=false` snapshots.
- `normalizeTournamentResults.ts` immutably demotes unsupported true flags, never promotes false ones, and repairs current phase/next-round metadata only when those demotions invalidated its completion evidence. Published completed standings retain authority. Normalize forecast, worker, Tracker and Prep colour consumers together; equivalent unresolved named text has the same sampling seed.

## Published target integrity (2026-10-02)

- A published target is confirmed only when the selected player and named opponent have unique roster identities and unique target assignments. Self-pairings, repeated rows (including identical rows), multiple opponents, or an opponent assigned twice return unavailable with the existing conflict message. A target opponent outside the roster retains the existing unmatched-roster refusal. Do not select the first conflicting row.
- The narrow guard preserves unique pending/known named assignments, occupied-seat solo awards, published precedence and unrelated/future rows. Phase/round metadata, numerical ranking/calibration, native parsing and the separate evidence resolver are unchanged. Shared desktop/phone consumers use the same source.
