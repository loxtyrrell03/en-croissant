# Engine resource controls and parity

The owner selected inline layout A in `design/engine-resources`. Native defaults
and live analysis tabs use that design through En's own per-profile/per-tab
settings, rather than Novelty's global analysis store. Novelty source is
`b186d2d7`. Phone Analysis A, compact navigation A and evaluation Settings A
remain separate approved designs.

CPU presets share the pure Quiet/Balanced/Faster policy with the PC service
source. Ten model cases and30 direct comparisons against the unchanged Novelty
module matched its numbers and maxima. An additional `canRecommend` guard rejects
infeasible aggregate minima. Native `engine_device_info` and gateway health.device
source expose logical threads and whole MiB without starting analysis; missing
memory is distinct from zero. OS memory is a momentary estimate, not a reservation.
The existing memory command/config/OnOff contracts stay intact.

Both native resource surfaces preserve exact saved/custom values, including
non-power-of-two memory and values above today's recommendation. A saved value
outside the current range remains visible with an associated description; its
range is not expanded to permit new edits above today's budget. Valid one-field
edits preserve other older choices. Engine UCI limits remain authoritative.
Presets change CPU/hash only, leaving lines, limits and other options unchanged.

`EngineSettingSlider` owns local pointer/key/exact-field drafts. Completion commits
once; Enter followed by blur does not duplicate a change. Escape, pointercancel,
lost capture and window blur discard unfinished gestures. A changed included-
engine budget cancels an old slider gesture, while an exact draft is retained and
checked against the latest range on completion. Hash stops retain valid custom
values and stay stable during a drag. Errors and saved-value descriptions span
the full field and are associated with the actual Mantine input. Existing help
supports focus, touch and dismissal; controls use native theme variables.

Live forms share path-cached native UCI inspection with its existing15-second
bound; this inspects metadata without a search. Closed forms mount no option or
device checks. Supported CPU options receive the shared controls; LCZero GPU,
remote, game setup and managed phone engines keep their own supported interfaces.
Recommendations count displayed CPU profiles plus other enabled tab instances,
including focus-paused instances, without moving their existing choices.

Unsynced edits stay in the original tab. Synced defaults stage immutable settings
and verify exact disk readback before publishing to analysis. Retry retains model,
revision and byte ownership; Restore previous only replaces exact owned uncertain
bytes. Cancellation settles exact prior/owned bytes through readback, without
writing over external/newer data or leaving a stuck pending snapshot. A global
write already in progress can finish for its original profile while replacement
unsynced settings remain intact. Stop/enable flags always come from current state;
no resource control manually starts a process or revives a paused listener.

Native request identity excludes default-only snapshots, avoiding redundant
restarts of unchanged unsynced tabs. Actual prior-listener integration failed two
cases; current behavior passes. Exhausted native request failures remain visible
beside Retry analysis, with CPU-only previous-resource restoration in the open
form. A saved preference receipt stays distinct from native search success.

Automatic first-use Balanced is scoped to successful missing-store bootstrap.
Only a confirmed absent engine-settings file qualifies; existing files, explicit
empty lists and default-looking saved values do not. The existing setup actor
waits for a bounded five-second device read, checks current model/directory/idle
ownership again, and divides the initial CPU budget among visible fresh profiles.
Other UCI settings, go limits, hidden flags, remote/GPU tuning and enabled states
are preserved. Later explicit registrations/imports retain En's per-profile
options: bootstrap initialization is not a global preset migration.

A failed/malformed device read or infeasible first-use budget creates no settings
file. Setup shows its resource-check status and existing retry action; late
replies/failures cannot replace newer choices, an active game or a removed owner.
A successful exact load/readback no longer creates an accidental empty file.
Submitting a new empty array still saves an intentional empty choice. The old
store reproduces the missing-readback failure; the corrected store and real setup
retry pass. This preserves genuine first use across failed reads and retries.

Current source verification:174 focused cases across18 files, full TypeScript,

IO/engine responses. Boundary tests cover older high values, new invalid edits,
changed counts, cancellation, keyboard selection and accessible descriptions.
No owner data, evaluation corpus, installed app or phone service was changed.
