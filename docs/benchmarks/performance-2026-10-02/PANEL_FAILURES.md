# Calculator failure isolation

The numerical solvers deliberately reject unsupported uncertainty, unresolved support and exhausted integration bounds. Those exceptions previously escaped the Stats component's render and could replace the entire view with an application error. The shared panel now catches each calculation independently, logs its diagnostic, and labels the affected estimate unavailable. It retains game results, openings, recent games, website ratings and any independently successful estimate. It does not substitute a guessed rating or mislabel a calculation failure as missing account data.

The cumulative-period graph still supplies its own headline without a duplicate calculation. A failed running history cannot remove a valid period estimate. Graph switching does not retain a stale failed chart. Replacing the input games allows the same mounted panel to recover; no reload, saved-state deletion or account change is required.

`scripts/qa-performance-errors.mjs` builds the actual shared component with synthetic games. An opponent SD of 5000 intentionally exceeds the solver's verified numerical range. Four cases per panel cover both-estimates failure and older-history-only failure at 1100 and 390 pixels, including comparison, graph switching, retained game results, independent period success and recovery in the same component. Expected calculation diagnostics are distinguished from page errors and unexpected console errors. External requests are blocked. Source hashes are checked before and after rendering.

The current Novelty primary panel and the retained En Croissant feature panel both pass all four cases. These represent the two existing panel variants: the primary's controlled period/confidence-band presentation and the feature's older inline period selector. Both layouts were visually inspected, and narrow edits preserve each variant. TypeScript checks pass for Novelty primary and En Croissant feature. `panel-failure-checks.json` retains the accepted receipts. The behavior is mirrored into Novelty, En Croissant and its phone-companion source checkout; installed apps, hosted services and physical devices were not changed or verified.

Run the browser script from the Novelty feature checkout, which already provides its existing browser-testing dependency, passing the target checkout as its argument. No additional browser dependency is needed in En Croissant.
