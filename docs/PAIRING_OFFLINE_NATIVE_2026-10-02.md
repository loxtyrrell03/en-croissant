# Offline native snapshot assembly, 2 October 2026

Live fetches and retained-page assembly now call the same metadata preparation, parsers, score merge, coverage and phase assembly. Acquisition stays separate. No retained page triggers a fallback network request. The original collector and live-probe executables were preserved; a distinct small harness builds the actual offline CLI statements.

`--offline-pages INPUT --output NEW_OUTPUT` accepts one UTF-8 JSON object with `schema: 1`, `sourceUrl`, retained RFC3339 `fetchedAt`, `detail`, `metadataFallbackRound`, `standings`, `pairings`, and `status`. Each page is `{status: "available", pageId, html}` or `{status: "unavailable", pageId, error}`. Round maps have unique positive keys. Page IDs are globally unique; unknown fields and duplicate round keys are rejected. IDs are references, not filesystem reads. Already-decoded HTML is supplied by the caller.

Success is `{schema: 1, kind: "tournament-offline-assembly", status: "complete", assembly: {schema: 1, snapshot, consumedPageIds, networkRequests: 0, transportVerified: false, decoderVerified: false, returnedBodyTournamentIdentityVerified: false}}`. `complete` means the constructor finished; missing or unreadable pages still produce warnings and unknown coverage. It is not source admission. `consumedPageIds` includes an unavailable page record whose error was inspected, as well as available pages read. It does not establish successful HTML parsing. Unrequested extras remain unconsumed; missing map entries do not invent page IDs.

Failures return a bounded `status: "failed"` envelope with an error and the same zero-network/false-proof fields, and exit 1. They make no consumed-page claim. Invalid/mixed CLI arguments exit 2. Both input and serialized output are limited to 256 MiB; output encoding is bounded before file creation. Oversized output becomes a small failed envelope. Output publication uses create-new and sync; collisions never overwrite, and a failed partial publication is retained. Caller timeout, immutable path verification and the combined task storage ceiling remain required.

A requested URL/page address never establishes returned-body tournament identity, charset correctness or HTTP trace proof. Those must be independently verified and hash-bound by the caller before source admission. Conditional offline metadata fallback uses only its declared retained standings page after the body round is verified; a declared round does not fill missing metadata. Existing online acquisition retains its historical unscoped final-ranking fallback. All subsequent parsing and assembly share the same functions. Missing pages stay missing. `Final Ranking after Round N` and `Final Ranking after N Rounds` require a strict positive round. A local `Round unknown` section resets pairing scope; `Round Robin` event titles remain benign. These two parser corrections also affect live fetch behavior and have focused fixtures.

The En core preserves readable empty registrations, event metadata and its existing online schedule fetch. Offline assembly supplies no schedule page and never requests art=14. Novelty's integration checkout preserves its pre-existing empty-roster rejection. Proposed Novelty-primary mirrors preserve that checkout's newer discovery, metadata, schedule and registration behavior, plus the metadata/discovery CLI modes; any offline flag routes through strict offline argument validation first.
